# Perp Hedge Spread Notifier

MVP Telegram-бота на Go для наблюдения за разницей цен одного perpetual-рынка в двух независимых экземплярах Lighter: Lighter Core и Lighter на Robinhood Chain. Бот сравнивает текущий спред с медианой за выбранное окно и отправляет уведомления, когда отклонение выходит за заданные пользователем границы. Торговые операции он не выполняет.

## Что умеет бот

- Получает публичные цены из REST API обеих площадок.
- Позволяет задать название актива, название рынка на каждой площадке, окно усреднения и нижнюю/верхнюю границы.
- Хранит настройки и историю измерений в локальной SQLite.
- Отправляет уведомление, если отклонение текущего спреда от медианы строго выше верхней границы или строго ниже нижней. Внутри диапазона и точно на его границах уведомлений нет.
- Зелёный маркер означает превышение верхней границы, красный — уход ниже нижней.

Расчёт: `spread_pct = (Robinhood price - Core price) / Core price * 100`. Положительное значение означает, что цена Robinhood выше Core. Для медианы бот запрашивает минутные исторические свечи mark price на обоих инстансах, сопоставляет закрытия свечей по времени и берёт медиану парных спредов за заданное окно. Окно может быть от 1 до 10080 минут (7 дней); результат кэшируется и обновляется не чаще одного раза в минуту. Незавершённая текущая минута исключается. Отклонение для проверки диапазона считается как `текущий спред - медиана` и измеряется в процентных пунктах. Для расчёта нужны минимум две совпавшие свечи.

Например, границы `-0.2` и `0.2` означают, что уведомление отправляется, если отклонение стало больше `0.2` п.п. (зелёный маркер) или меньше `-0.2` п.п. (красный маркер). При значениях от `-0.2` до `0.2` включительно уведомлений нет. Пока условие выхода за границы сохраняется, уведомление повторяется не чаще раза в 20 секунд. Сообщение показывает текущие цены, медиану и отклонение. Это только уведомления для ручной оценки хеджа, не торговая рекомендация.

## Требования

- Go 1.24 или новее.
- Telegram-бот, созданный через [@BotFather](https://t.me/BotFather).
- Доступ к Telegram Bot API и публичным API Lighter.

## Запуск

Скопируйте `config.yaml.example` в локальный `config.yaml`. Значения настройки находятся в YAML, а секрет Telegram передаётся через переменную окружения `TELEGRAM_BOT_TOKEN`, указанную в YAML как `${TELEGRAM_BOT_TOKEN}`.

```sh
cp config.yaml.example config.yaml
chmod 600 config.yaml
export TELEGRAM_BOT_TOKEN='токен-от-BotFather'
go run ./cmd/bot
```

Токен берите у @BotFather и задавайте через secret manager или защищённое окружение процесса. Файл `config.yaml` исключён из Git. Не сохраняйте токен в `config.yaml`, Dockerfile, аргументах командной строки или логах.

Список разрешённых Telegram user ID задаётся в `telegram.allowed_user_ids`. Если список пуст, первый пользователь, написавший `/start`, получает доступ. Для личного или общего развёртывания рекомендуется явно задать allowlist.

База `spreads.db` хранится в корне проекта. Файл SQLite и его WAL/SHM-файлы получают права `0600`; не ослабляйте их и не публикуйте базу или её резервные копии.

Не добавляйте токен в Dockerfile, systemd unit, логи, коммиты или сообщения об ошибках. При утечке немедленно отзовите токен у BotFather.

## Команды Telegram

```text
/start
/help
/add SYMBOL CORE_MARKET RH_MARKET WINDOW LOW HIGH
/list
/remove SYMBOL
```

Пример, запрошенный для Anthropic:

```text
/add ANTHROPIC ANTHROPIC ANTHROPIC 1h -0.5 0.5
```

`WINDOW` задаётся числом минут или длительностью с суффиксом `m`, `h`, `d`, `w` (например, `60`, `1h`, `1d`, `1w`). Максимальное окно — одна неделя.

Здесь `ANTHROPIC` — лишь пример символа/рынка, а не подтверждение наличия такого листинга. Пользователь должен указать реальные имена рынков, существующие на обеих площадках. Имена сверяются без учёта регистра. Если рынок или цена не найдены, ошибка записывается в лог приложения; опрос продолжится на следующем цикле.

## Конфигурация

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `TELEGRAM_BOT_TOKEN` | обязателен | Переменная окружения с токеном Telegram Bot API |
| `telegram.allowed_user_ids` | `[]` | Разрешённые ID; пустое значение включает захват доступа первым `/start` |
| `database.path` | `./spreads.db` | Путь к локальной SQLite БД; относительный путь считается от каталога `config.yaml` |
| `polling.interval_seconds` | `10` | Интервал опроса (5–300 секунд) |
| `lighter.core_api` | `https://mainnet.zklighter.elliot.ai` | REST base URL Core |
| `lighter.robinhood_api` | `https://api.rh.lighter.xyz` | REST base URL Robinhood Chain |

Core и Robinhood Chain — отдельные биржевые экземпляры со своими рынками и ликвидностью. См. [официальную документацию Lighter API](https://docs.lighter.xyz/api) и [документацию Robinhood Chain о Lighter Domains](https://docs.robinhood.com/chain/lighter-domains/).

## Структура кода

- `cmd/bot/main.go` — только настройка контекста, создание и запуск бота.
- `cmd/bot/config.go` — загрузка и проверка `config.yaml`.
- `cmd/bot/telegram.go` и `commands.go` — Telegram long polling и обработка команд.
- `cmd/bot/storage.go` — схема SQLite и операции с настройками/историей.
- `cmd/bot/marketdata.go` и `monitor.go` — получение цен и расчёт сигналов.
- `go.mod` — зависимости; SQLite реализована библиотекой `modernc.org/sqlite` без CGO.
- `config.yaml.example` — пример настроек; содержит только ссылку на переменную окружения для токена.

Текущий спред берётся из `GET /api/v1/orderBookDetails` на каждой площадке: сначала `mark_price`, затем `last_trade_price` как резерв. Для исторической медианы используется `GET /api/v1/markPriceCandles` с интервалом `1m`; API запрашивается отдельно для каждого инстанса и его собственного `market_id`. При окнах свыше 500 минут данные загружаются частями из-за лимита API в 500 свечей на запрос. Кэш медианы в памяти бота обновляется при смене минутной свечи, чтобы не запрашивать историю на каждом цикле опроса. Старые снимки, накопленные предыдущими версиями, остаются в SQLite, но больше не участвуют в расчёте. Этот расчёт не учитывает комиссии, funding, глубину книги, задержки API или проскальзывание.
